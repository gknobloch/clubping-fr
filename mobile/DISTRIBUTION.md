# iOS distribution (EAS Build)

The mobile app is an Expo project using **CNG (Continuous Native Generation)**: the
native `ios/` and `android/` folders are generated by `expo prebuild` and are **not**
committed to git (see `.gitignore`). Because of this, **Xcode Cloud cannot be used** —
it clones the repo and finds no `ios/ClubPing.xcworkspace` to build, failing with:

```
xcodebuild: error: '.../mobile/ios/ClubPing.xcworkspace' does not exist.
```

Instead, iOS builds and App Store submission go through **EAS Build**, which regenerates
the native project (prebuild + CocoaPods), signs it, and uploads to App Store Connect.

## One-time setup

1. Install the EAS CLI (once, globally):
   ```
   npm install -g eas-cli
   ```
2. Log in with the Expo account that owns the project:
   ```
   eas login
   ```
3. Link this project to an EAS project. This writes `extra.eas.projectId` into `app.json`:
   ```
   eas init
   ```

## Build profiles

Defined in `eas.json`:

| Profile       | Distribution | Notes                                              |
| ------------- | ------------ | -------------------------------------------------- |
| `development` | internal     | Dev client, iOS simulator build                    |
| `preview`     | internal     | Ad-hoc / internal testing, real device             |
| `production`  | store        | App Store build, auto-increments the build number  |

## Common commands

Run from the `mobile/` directory:

```
# Production build for the App Store
npm run build:ios

# Internal test build (real device)
npm run build:ios:preview

# Submit the latest production build to App Store Connect
npm run submit:ios
```

`npm run submit:ios` uploads the most recent finished `production` build. On first run,
EAS will prompt for the App Store Connect credentials / API key and store them for reuse.
